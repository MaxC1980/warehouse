# 代码质量规范

从已修复的问题中提炼的开发规范，避免重复犯错。

---

## 一、安全规范

### 0. 密码必须 hash 存储，自动迁移兼容明文
所有密码用 `werkzeug.security.generate_password_hash` 存储，禁止明文。首次登录成功后原地覆盖为 hash（不增加新列），用户无感知。
```python
from werkzeug.security import generate_password_hash, check_password_hash
# 写: generate_password_hash(password)
# 验: check_password_hash(stored_hash, password)
# 区分 hash vs 明文: stored.startswith(('pbkdf2:', 'scrypt:', 'argon2:'))
```

**自动迁移模式**: 首次登录成功后，原地覆盖为 hash，用户无感知。不增加新列，不强制重置密码。

### 1. 禁止硬编码密钥
`SECRET_KEY` 必须用 `secrets.token_hex(32)` 随机生成，不硬编码。持久化通过环境变量。

### 2. API 必须鉴权
所有 `/api/` 路由必须通过 `before_request` 检查 `session['user_id']`。新增 API 路由不需要单独加登录检查，全局钩子已覆盖。

### 3. 写操作必须校验 CSRF
POST/PUT/DELETE/PATCH 必须校验 `X-Requested-With: XMLHttpRequest` header。前端 `apiRequest()` 已自动携带。

### 4. innerHTML 必须转义
模板中 innerHTML 的数据库字段必须用 `escapeHtml()` 包裹。禁止裸 `${var}` 直接拼接。
```javascript
// 正确
td.innerHTML = `${escapeHtml(item.name)}`;
// 错误
td.innerHTML = `${item.name}`;
```

### 5. JS 上下文用 tojson
Jinja2 变量嵌入 `<script>` 时必须用 `{{ value | tojson }}`，不能用 `'{{ value }}'`。
```javascript
// 正确
const status = {{ order.status | tojson }};
// 错误
const status = '{{ order.status }}';
```

### 6. 业务异常用 ValueError，不用 Exception
Service 层业务校验用 `raise ValueError(msg)`，Route 层 `except ValueError` 返回 400。`except Exception` 返回通用 500，不暴露内部信息。
```python
# 正确
if quantity < 0:
    raise ValueError('数量不能为负')
# 错误
if quantity < 0:
    raise Exception('数量不能为负')
```

### 7. 异常必须记录日志
`except Exception` 块必须加 `logger.exception()` 记录异常堆栈，否则生产环境无法排查。
```python
except ValueError as e:
    return jsonify({'error': str(e)}), 400
except Exception as e:
    logger.exception('操作失败')
    return jsonify({'error': '服务器内部错误'}), 500
```

### 8. 页面权限用 endpoint 精确匹配
页面权限控制用 `request.endpoint` 映射，不用路径前缀 `startswith()`。前缀匹配会导致 `/materials/1/edit` 被 `/materials` 误判为 view 权限。

### 9. 新增路由必须加权限
新增写操作路由必须加 `@require_permission('module', 'action')` 装饰器。新增页面路由必须在 `PAGE_ENDPOINT_PERMISSIONS` 中配置。

## 二、数据规范

### 10. 禁止 SELECT *
查询必须写明需要的列名，禁止 `SELECT table.*`。

### 11. 不使用 PRAGMA foreign_keys
项目不用外键约束，引用检查在 Service 层手动做。禁止在代码中 `PRAGMA foreign_keys = ON`。

### 12. 数值显示必须 toFixed(2)
前端所有数值显示必须用 `Number(value).toFixed(2)`，避免浮点精度问题（如 `90.17999999999999`）。
```javascript
// 正确
td.textContent = Number(item.quantity).toFixed(2);
// 错误
td.textContent = item.quantity;
```

### 13. 导出不限制 per_page
导出功能用 `per_page=None`，Service 层支持跳过 LIMIT。不硬编码 `per_page=10000`。

### 14. LEFT JOIN 一对多要子查询
LEFT JOIN 可能产生一对多重复行时，用子查询 `SELECT ... LIMIT 1` 替代。
```sql
-- 正确
SELECT (SELECT name FROM table2 WHERE id = t1.ref_id LIMIT 1) FROM table1 t1
-- 错误
SELECT t2.name FROM table1 t1 LEFT JOIN table2 t2 ON t2.ref_id = t1.id
```

## 三、路由规范

### 15. request.get_json 必须加 silent
所有 `request.get_json()` 调用必须用 `request.get_json(silent=True) or {}`，空/非 JSON 请求不报 500。

### 16. 路由文件不要 import 未使用的模块
删除未使用的 import，保持代码整洁。

### 17. 同一事务内操作
多个数据库操作必须在同一连接/事务内完成，不要开独立连接。
```python
# 正确
with get_db_connection() as conn:
    cursor = conn.cursor()
    # 操作 A
    # 操作 B（同一事务）
# 错误
conn1 = get_db_connection()  # 操作 A
conn2 = get_db_connection()  # 操作 B（不同事务）
```

## 四、前端规范

### 18. 禁止裸 except
Python 代码禁止 `except:` 捕获所有异常，必须用 `except Exception:`。

### 19. 下拉框数据用配置
固定选项（如部门列表）用后端配置或前端常量，不用自由文本输入。
```javascript
// 正确
const departments = ['管理部', '研发部', '品质部', '工程部', '采购部', '仓储部'];
// 错误
<input type="text" name="department">
```

### 20. 字符串包含不等于精确匹配
判断字符串是否在列表中时，用 `split` 后 `includes`，不用直接 `includes`（会误匹配子串）。
```javascript
// 正确
user.roles.split(', ').includes('操作员')
// 错误（"出库操作员" 也会匹配）
user.roles.includes('操作员')
```

### 21. onclick 中不用 escapeHtml
`escapeHtml` 是 HTML 层转义，onclick 是 JS 上下文，HTML 解析器会在 JS 执行前还原实体。onclick 只传 ID，函数内部查数据。
```javascript
// 正确
onclick="showUserRoles(${u.id})"
// 错误（escapeHtml 的 &#39; 会被还原为 '）
onclick="showUserRoles(${u.id}, '${escapeHtml(u.username)}')"
```

### 22. 统一用 apiRequest，不用原生 fetch
所有 API 调用用 `apiRequest()`，自动携带 CSRF header、401 跳转、错误处理。文件下载用 `window.location.href`（二进制响应不能用 apiRequest）。
```javascript
// 正确
const result = await apiRequest('/materials', { method: 'POST', body: JSON.stringify(data) });
// 错误（绕过 CSRF、错误处理）
const response = await fetch('/api/materials', { method: 'POST', body: JSON.stringify(data) });
```

### 23. 权限矩阵要覆盖所有 action 类型
渲染权限矩阵时，actions 列表要包含所有可能的 action（view/edit/approve/manage），不能只写死三种。按模块过滤适用的 actions，避免遗漏。
```javascript
// 正确
const actions = ['view', 'edit', 'approve', 'manage'];
// 错误（manage 权限会丢失）
const actions = ['view', 'edit', 'approve'];
```

### 24. 页面路由调 Service 要有 try/except
页面路由直接调用 Service 方法时，必须加 try/except。异常时重定向到列表页，不暴露原始错误。
```python
# 正确
try:
    order = OrderService.get_in_order_by_id(order_id)
    return render_template('in_order_detail.html', order=order)
except Exception:
    return redirect('/in-orders')
```

### 25. 文件上传要校验扩展名和大小
文件上传端点必须校验扩展名（白名单）和文件大小（`MAX_CONTENT_LENGTH`）。不校验可被上传恶意文件或超大文件 DoS。
```python
# 正确
ext = file.filename.rsplit('.', 1)[-1].lower()
if ext not in Config.ALLOWED_EXTENSIONS:
    return jsonify({'error': '格式不支持'}), 400
```

### 26. 分页参数要有上下限
分页参数必须 `max(1, min(per_page, max_value))`，防止负数和零。
```python
# 正确
return max(1, min(per_page, max_value))
# 错误（per_page=-1 会通过）
return min(per_page, max_value)
```

### 27. Jinja2 变量注入 JS 必须处理 Undefined
`{{ value | tojson }}` 对 Undefined 会报错。用 `{{ value | default(none) | tojson }}` 处理可选参数。
```javascript
// 正确
const orderId = {{ order_id | default(none) | tojson }};
// 错误（新建页面 order_id 未定义时报错）
const orderId = {{ order_id | tojson }};
```

### 28. 循环内查询要批量优化（N+1 问题）
循环内逐行查数据库是 N+1 问题。先批量查询，用 dict 缓存结果。
```python
# 正确
material_ids = list(set(item['material_id'] for item in items))
cursor.execute(f"SELECT id, is_reusable FROM material WHERE id IN ({placeholders})", material_ids)
reusable_map = {row['id']: row['is_reusable'] == 1 for row in cursor.fetchall()}

# 错误（每个 item 查一次）
for item in items:
    cursor.execute("SELECT is_reusable FROM material WHERE id = ?", (item['material_id'],))
```

### 29. N+1 一对多用子查询
LEFT JOIN 一对多产生重复行时，用子查询 `SELECT ... LIMIT 1` 替代。批量查询用 `WHERE id IN (...)`。
```sql
-- 正确
SELECT (SELECT name FROM table2 WHERE id = t1.ref_id LIMIT 1) FROM table1 t1
-- 错误（重复行）
SELECT t2.name FROM table1 t1 LEFT JOIN table2 t2 ON t2.ref_id = t1.id
```

### 30. 权限变更要刷新 session 缓存
修改角色权限或用户角色后，受影响用户的 session 缓存不更新，需要重新登录才生效。当前设计接受此限制（用户少、变更频率低）。

**实现**: `require_permission` 装饰器从 `session['permissions']` 查 set，不再走 DB，避免每次 API 请求多一次连接和 3 表 JOIN。

### 31. SQL LIKE 通配符必须转义
用户输入用于 LIKE 查询时，必须转义 `%` 和 `_`，防止被当作通配符。用 `escape_like()` 工具函数 + `LIKE ? ESCAPE '\\'`(Python 字符串中反斜杠需转义，推荐用原始字符串 `r'\\'` 避免多层转义)。
```python
from utils.sql import escape_like
kw = escape_like(keyword)
cursor.execute(r"SELECT * FROM t WHERE name LIKE ? ESCAPE '\\'", (f'%{kw}%',))
```

### 32. 错误/成功消息统一中文
所有面向用户的 API 响应消息必须用中文，不用英文。包括错误提示和成功提示。
```python
# 正确
return jsonify({'error': '入库单不存在'}), 404
return jsonify({'message': '入库单已删除'})
# 错误
return jsonify({'error': 'Order not found'}), 404
return jsonify({'message': 'Order deleted'})
```

### 33. 文件上传校验扩展名+魔数
只校验扩展名不够，攻击者可改扩展名绕过。必须同时校验文件头魔数（magic bytes）。
```python
header = file.read(8)
file.seek(0)
if ext == 'xlsx' and header[:2] != b'PK':
    return '文件内容与扩展名不匹配'
```

## 七、本次改进记录 (2026-06-13)

### 34. 大函数拆分模式
超过 100 行的函数应拆分为多个子函数，每个子函数单一职责。
- 主函数做编排（< 30 行）
- 子函数做具体逻辑（< 50 行）
- 子函数命名以 `_` 前缀表示内部使用

### 35. 业务规则集中定义
避免同一业务规则在多处重复定义。抽为独立函数，SQL 端和 Python 端共用。
```python
# 正确：规则集中
def _expiry_filter_bounds(status):
    """status → (operator, ymd_value, require_non_null)"""
    ...

# SQL 端和 Python 端都调用
bounds = _expiry_filter_bounds(status)
```

### 36. 动态 SQL 构建工具
重复的动态 UPDATE SQL 构建模式应抽为工具函数，带字段白名单防注入。
```python
def build_update_sql(table, data, allowed_fields, id_column='id'):
    """根据 data 中存在的字段动态构建 UPDATE SQL"""
    ...
```

### 37. 页面路由与 API 路由分离
页面路由（渲染模板）和 API 路由（返回 JSON）应分 Blueprint，不要混在 `create_app.py` 工厂函数内。
- 页面路由: `routes/pages.py` (Blueprint `pages`)
- API 路由: `routes/*.py` (Blueprint `*_bp`)

### 38. Service 层抽取
Route 层不要直接操作 DB，应通过 Service 层。写操作统一 `ValueError` → 400，`Exception` → 500 + logger。

### 39. import 风格统一
- 所有 import 放文件顶部，不在函数内延迟 import（Flask 循环导入除外）
- import 顺序: 标准库 → 第三方 → 本地
- 变量定义（如 `logger = ...`）放在所有 import 之后

### 40. 死代码清理
- 删除未使用的 import、变量、函数
- 重构后遗留的旧方法（如 `get_all_roles()` 被 `get_all_roles_with_permissions()` 替代）应删除
- 测试中的旧调用同步更新

### 41. 文档与代码同步
- 数据字典.md 必须与 database.py 表结构一致
- 删除与 CLAUDE.md 重复的文档（如 docs/编码规则.md）
- 规范条文消除歧义，加代码示例

### 42. 限流字典用 LRU 防内存泄漏
模块级 dict 用于限流/缓存时，必须设容量上限，防止长期运行内存累积。
```python
from collections import OrderedDict

class LRUDict:
    def __init__(self, maxsize):
        self.data = OrderedDict()
        self.maxsize = maxsize
    ...
```
