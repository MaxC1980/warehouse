# 代码质量改进记录

从已修复的问题中提炼的开发规范，避免重复犯错。

**结构**: 一至六为当前规范，七为改进历史。

---

## 一、安全

### 1. 禁止硬编码密钥
`SECRET_KEY` 用 `secrets.token_hex(32)` 随机生成。持久化通过环境变量。

### 2. 密码必须 hash 存储
所有密码用 `werkzeug.security.generate_password_hash`，禁止明文。首次登录成功后原地覆盖为 hash（不增加新列），用户无感知。
```python
# 区分 hash vs 明文
_HASH_PREFIXES = ('pbkdf2:', 'scrypt:', 'argon2:')
def _is_hash(value): return value.startswith(_HASH_PREFIXES)
```

### 3. API 必须鉴权
所有 `/api/` 路由必须通过 `before_request` 检查 `session['user_id']`。新增 API 路由不需单独加登录检查，全局钩子已覆盖。

### 4. 写操作必须校验 CSRF
POST/PUT/DELETE/PATCH 必须校验 `X-Requested-With: XMLHttpRequest` header。前端 `apiRequest()` 已自动携带。

### 5. innerHTML 必须 escapeHtml
模板中 innerHTML 的数据库字段必须用 `escapeHtml()` 包裹。禁止裸 `${var}` 拼接。

### 6. onclick 只传 ID
onclick 是 JS 上下文，HTML 解析器会还原实体，`escapeHtml` 在 onclick 里失效。函数内查数据。
```javascript
onclick="editUser(${u.id})"           // 正确
onclick="editUser(${u.id}, '${x}')"   // 错误
```

### 7. 业务异常用 ValueError
Service 层业务校验 `raise ValueError(msg)`，Route 层 `except ValueError` → 400。`Exception` → 500 + `logger.exception`，不暴露内部信息。
```python
if quantity < 0: raise ValueError('数量不能为负')
except ValueError as e: return jsonify({'error': str(e)}), 400
except Exception: logger.exception('操作失败'); return 500
```

### 8. 错误/成功消息统一中文
API 响应的 error/message 全中文，不混英文。

## 二、数据

### 9. 禁止 SELECT *
查询必须写明列名，禁止 `SELECT *` 和 `SELECT table.*`。

### 10. 不使用 PRAGMA foreign_keys
项目不用外键约束，引用检查在 Service 层手动做。禁止 `PRAGMA foreign_keys = ON`。

### 11. 数值显示 toFixed(2)
前端展示前 `Number(x).toFixed(2)`，避免 `0.1 + 0.2 = 0.30000000000000004`。

### 12. 导出不限制 per_page
导出功能传 `per_page=None`，Service 层支持跳过 LIMIT。

### 13. 避免重复查询/行
- **N+1**：循环内逐行查 → 先 `WHERE id IN (...)` 批量查，dict 缓存
- **JOIN 行重复**：LEFT JOIN 一对多产生重复行 → 改子查询 `SELECT ... LIMIT 1`
```python
material_ids = list(set(item['material_id'] for item in items))
cursor.execute(f"SELECT id, is_reusable FROM material WHERE id IN ({placeholders})", material_ids)
reusable_map = {row['id']: row['is_reusable'] == 1 for row in cursor.fetchall()}
```

## 三、路由

### 15. 页面权限用 endpoint 精确匹配
`request.endpoint` 映射，不用路径前缀 `startswith()`。前缀匹配 `/materials/1/edit` 会被误判。

### 16. 新增路由必须加权限
写操作加 `@require_permission('module', 'action')`。页面路由在 `PAGE_ENDPOINT_PERMISSIONS` 配置。

### 17. request.get_json 必须 silent
`request.get_json(silent=True) or {}`，空/非 JSON 请求不报 500。

### 18. 同一事务内操作
多个 DB 操作在同一连接/事务内完成，不要开独立连接。

### 19. 页面路由调 Service 要有 try/except
页面路由直接调 Service 时加 try/except。异常时重定向到列表页，不暴露原始错误。

### 20. 文件上传必须校验
- 扩展名白名单（`Config.ALLOWED_EXTENSIONS`）
- 文件头魔数（`PK` for xlsx, `\xd0\xcf\x11\xe0` for xls），防扩展名绕过
- `MAX_CONTENT_LENGTH` 防 DoS

### 21. 分页参数用 utils.pagination
`get_per_page(default, max_value)`，不要手写 max/min。

### 22. 错误处理装饰器统一（@handle_service_errors）
所有调用 Service 的 API 路由加 `@handle_service_errors`：
- `ValueError` → 400 + 透传消息
- `Exception` → 500 + `logger.exception`

放在 `@require_permission` 之内（更内层）。**替代手写 try/except**，风格统一。

## 四、前端

### 23. JS 上下文用 tojson
Jinja2 变量嵌入 `<script>` 用 `{{ value | tojson }}`，不用 `'{{ value }}'`。

### 24. 模板变量注入 JS 处理 Undefined
`{{ value | tojson }}` 对 Undefined 报错。用 `{{ value | default(none) | tojson }}`。

### 25. 统一用 apiRequest
所有 API 调用用 `apiRequest()`，自动携带 CSRF、401 跳转、错误处理。文件下载用 `window.location.href`（二进制响应不能用 apiRequest）。

### 26. 字符串包含用 split + includes
`user.roles.split(', ').includes('操作员')`，不用 `user.roles.includes('操作员')`（子串误匹配）。

### 27. 权限矩阵覆盖所有 action
actions 列表要包含所有可能类型（view/edit/approve/manage），按模块过滤适用项。

### 28. 下拉框数据用配置
固定选项用后端配置或前端常量，不用自由文本输入。

---

## 五、SQL

### 29. LIKE 通配符必须转义 + ESCAPE
用户输入做 LIKE 必须用 `escape_like()` 转义，SQL 加 `ESCAPE '\\'`（Python 源 1 字符 `\`）。
- **推荐用 `build_like_clause(columns, keyword, params, prefix=False)` 工具**（见 `utils/sql.py`），自动处理转义和参数追加
- `prefix=True` 用 `'kw%'` 前缀匹配，`False` 用 `'%kw%'` 模糊匹配（默认）
- **不要手写** `kw = escape_like(...); params.extend([...])` 重复模式

### 30. 动态 UPDATE 用 build_update_sql
字段白名单防 SQL 注入和误改敏感字段。详见 `utils/sql.py`。

### 31. 业务规则集中定义
同一规则不在 SQL 端和 Python 端重复。抽 `_rule()` 函数，两端共用。

### 32. 日期处理用 SQLite 内置函数
`strftime('%Y%m%d', expiry_date)` 一步完成，**不用**手拆 `INSTR/SUBSTR/PRINTF`。手拆易错且不可移植。

## 六、项目特性

### 33. SECRET_KEY 每次启动随机生成
`secrets.token_hex(32)`，重启后 session 失效。设 `SECRET_KEY` 环境变量可持久化。

### 34. 限流/缓存 dict 用 LRUDict
模块级 dict 必须用 `LRUDict(maxsize=...)`，防长期运行内存泄漏。登录限流（IP+账号，5/15min）已用 `LRUDict(maxsize=10000)`。

### 35. Page 路由与 API 路由分 Blueprint
- 页面路由：单独 Blueprint（`pages_bp`），渲染模板
- API 路由：按模块分 Blueprint，返回 JSON

### 36. Route 只调 Service，不直接碰 DB
写操作统一 `ValueError` → 400，`Exception` → 500 + logger。Service 层负责事务、引用检查、业务规则。

### 37. import 风格
- 所有 import 顶部（Flask 循环导入除外）
- 顺序：标准库 → 第三方 → 本地
- `logger = ...` 放 import 之后

### 38. 死代码及时清理
重构后遗留的旧方法、旧调用、未使用 import 同步删除。

### 39. 业务连续性优先
单步改动涉及多层（装饰器/Service/页面/模板）时，逐层回归测试。重构允许保留兼容旧 API 一段时间。

### 40. 文档与代码同步
修改表结构、业务规则、权限模型时，同步更新 `docs/项目说明.md` / `docs/业务逻辑.md` / `docs/权限管理.md` / `docs/数据字典.md` / `docs/通用开发规范.md`。
