# 业务逻辑

## 一、库存

### 1.1 库存查询（库存页面）

**数据来源**：`inventory` 表（仅 `quantity > 0` 的记录）

**状态判断**：
- **过期**：有效期日期 < 今天（空日期不判断，显示正常）
- **正常**：其他情况

**待审入库**：
- 来源：`in_order` status='pending' 的入库明细
- 匹配逻辑：按 `(material_id, batch_no)` 匹配已有库存行
  - 匹配到 → 在该行的 `pending_in` 字段累加数量
  - 匹配不到 → 新增一行，`quantity=0`，`pending_in=待审数量`，`status=正常`
- 同物料同批次的多条待审合并到同一行

**待审出库**：
- 来源：`out_order` status='pending' 的出库明细
- 匹配逻辑：按 `(material_id, batch_no)` 匹配已有库存行
- **不新增行**，只在已有库存行上累加 `pending_out`

**浮点精度**：数量运算使用 `ROUND(quantity, 2)`

### 1.2 库存更新

**入库审核时**：UPSERT on `(material_id, batch_no)`
- 批次已存在 → `quantity = quantity + ?`
- 批次不存在 → INSERT 新记录

**出库审核时**：扣减库存
- 指定批次 → 从该批次扣减（需库存足够）
- 未指定批次 → 按有效期升序扣减最早批次

**可回用物料**：出库审核时扣减库存（和普通物料一样），退库审核时恢复剩余库存

### 1.3 库存导入

- 批次号为空时自动生成：`IMP-YYYYMMDDHHMMSS`
- 同一物料同一批次存在时更新数量，否则新增

## 二、订单

### 2.1 单号生成

| 订单类型 | 前缀 | 格式 |
|---------|------|------|
| 入库单 | RK | `RK-YYYYMMDD-序号`（当日自增） |
| 出库单 | CK | `CK-YYYYMMDD-序号`（当日自增） |
| 退库单 | TK | `TK-YYYYMMDD-序号`（当日自增） |

### 2.2 入库单

**状态**：`pending` → `approved`

**审核流程**：
1. 验证 status='pending'
2. 遍历明细，UPSERT inventory
3. 更新 status='approved'

**编辑/删除条件**：仅 `pending` 状态可操作

### 2.3 出库单

**状态**：`pending` → `approved`（`completed` 仅历史数据保留，新流程不再产生）

**审核流程**：
1. 验证 status='pending'
2. 遍历明细：按批次扣减库存（可回用物料和普通物料一样处理）
3. 更新 status='approved'

**编辑/删除条件**：仅 `pending` 状态可操作

### 2.4 退库单

**防重复**：同一出库单内相同 `(material_id, batch_no)` 只能有一个 `approved` 状态的退库，不同物料批次互不影响

**审核流程**：
1. 逐明细校验无重复 approved 退库
2. 按物料类型计算退回数量，统一回加库存 `inventory.quantity += 退回数量`：
   - **可回用物料**：更新 `reusable_material_weight` 称重记录，净用量 = 领用毛重 - 退回毛重，退回数量 = `actual_quantity - 净用量`
   - **普通物料**：退回数量 = 直接填写的数量
3. `out_order_item.actual_quantity` 保持原出库值不变（不修改）
4. **不修改** `out_order.status`（保持 `approved`，同单其他物料批次可继续退库）

**创建入口**：出库单详情页（已审核状态）点击退库，逐行填写退回数量/退回毛重

**校验规则**：
- 退库明细的 `out_order_item_id` 必须属于 `related_out_order_id`，不匹配则拒绝
- 可回用：净用量（`net_weight`）不能为负数（退库毛重不能大于初始毛重）
- 可回用：剩余库存（`original_qty - net_weight`）不能为负数

**可回用物料净用量**：`initial_gross_weight - return_gross_weight`

## 三、物料

### 3.1 可回用物料

通过 `material.is_reusable = 1` 标识

**出库流程**：
- 和普通物料一样扣减库存
- 创建 `reusable_material_weight` 记录（status='checked_out'）

**退库流程**：
- 计算净用量：`initial - return`
- 恢复库存：`out_order_item.actual_quantity - 净用量`
- 更新 `reusable_material_weight`（status='returned'）

### 3.2 删除限制

有入库/出库记录 或 库存 > 0 → 禁止删除

## 四、权限（RBAC）

基于角色的访问控制，替代旧的 3 级数值权限。

**权限结构**：`role` → `role_permission` → `permission(module, action)`

**默认角色**：

| 角色 | 权限 | 说明 |
|------|------|------|
| 管理员 | 全部 31 条 | 系统内置，不可删除、不可编辑 |
| 操作员 | view + edit（不含 approve、manage） | 系统内置，不可删除、不可编辑 |
| 查看员 | 仅 view | 系统内置，不可删除、不可编辑 |

系统角色权限按定义自动补齐：启动时检查缺失权限并补充，不删除已有权限。

**权限模块**（31 条）：

| 模块 | view | edit | approve/manage |
|------|------|------|----------------|
| 首页 | ✓ | - | - |
| 大类管理/小类管理/物料管理/供应商/员工管理 | ✓ | ✓ | - |
| 入库单/出库单/退库单 | ✓ | ✓ | ✓ |
| 产品管理 | ✓ | ✓ | - |
| 库存查询/称重记录 | ✓ | - | - |
| 库存报表/出入库报表/入库明细报表/出库明细报表/汇总统计 | ✓ | - | - |
| 角色管理/用户管理 | - | - | manage |

**控制层级**：
- 页面：`before_request` 路径映射拦截
- API：`@require_permission` 装饰器
- 模板：`has_perm()` 控制菜单和按钮显隐

**管理页面**：
- `/admin/roles-page` — 角色管理（创建/编辑/删除角色，权限矩阵勾选）
- `/admin/users-page` — 用户管理（新增/删除用户，重置密码，分配角色）

**admin 账号保护**：
- 不能删除
- 不能修改角色（锁定为管理员）
- 可以重置密码

**新用户默认角色**：查看员（仅 view 权限）

## 五、报表

### 5.1 库存汇总报表

按物料分组，`quantity < safety_stock` → 显示"低于安全库存"

### 5.2 入库明细报表

按入库单明细展示，金额 = `数量 × 单价`

### 5.3 出库明细报表

按出库单明细展示，包含部门信息

### 5.4 出入库报表（库存流水）

按物料汇总展示，跨 `in_order_item` 和 `out_order_item` 和 `return_order_item` 统计。

**列定义**：
| 列 | 数据来源 | 公式 |
|---|---------|------|
| 期初数 | 截止查询起始日前的累计 | 期初入库 - 期初出库 + 期初退库 |
| 入库数 | 查询期间内的入库 | `SUM(in_order_item.quantity)` |
| 出库数 | 查询期间内的出库 | `SUM(out_order_item.actual_quantity)` |
| 退库数 | 查询期间内的退库 | `SUM(out_order_item.actual_quantity - return_order_item.actual_net_weight)` |
| 期末数 | 汇总 | 期初 + 入库 - 出库 + 退库 |

## 六、数据库设计

### 6.1 单表设计

`inventory` 表以 `(material_id, batch_no)` 为 UNIQUE KEY，同一物料同一批次只存一条记录。

### 6.2 订单关联

| 表 | 关联 |
|---|------|
| in_order_item | order_id → in_order.id |
| out_order_item | order_id → out_order.id |
| inventory | material_id → material.id, in_order_item_id → in_order_item.id |
| return_order_item | return_order_id → return_order.id, out_order_item_id → out_order_item.id |
| reusable_material_weight | out_order_item_id → out_order_item.id |

## 七、产品与 BOM

### 7.1 数据模型

- `product` — 成品/半成品，独立编码体系 (与 `material` 分离)
- `bom` — 产品物料清单，单层 `(product_id, material_id, qty_per_unit)` 唯一约束
- `bom_substitute` — 主物料的替代物料 `(bom_id, material_id, priority)` 唯一约束

### 7.2 BOM 管理

- 同一产品内相同物料不能重复（唯一约束）
- 替代物料不能与主物料相同
- 替代物料库存合并计入主物料可用量（缺料检查和最大可产数均适用）
- BOM 删除级联：删除产品时自动清除其 BOM 行 + 替代关系

### 7.3 用料计算（原缺料计算）

输入：`[{product_id, quantity}]`，支持多产品同时计算
输出：按物料聚合，每行含 `required / main_stock / substitute_stock / available / shortage`

**可用量 = 主库存 + 替代库存合计（所有替代物料的库存之和）**

**过期排除**：可选排除过期批次 (`expiry_date < today`)，未设置过期日期的库存不过期

**禁用产品**：`product.disabled=1` 的产品不显示在用料计算下拉中

### 7.4 最大可生产数

算法：`min(floor(available_i / qty_per_unit_i))` 遍历 BOM 所有物料
瓶颈物料：取最小值的物料编码

### 7.5 产品复制

- 名称追加 "副本"
- 编码自动生成（前缀 + 自增数字）
- BOM 物料 + 替代关系同步复制
