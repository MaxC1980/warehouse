# 通用开发规范

跨项目适用的开发规范，从本项目实际修复中提炼。

只列强制规定与项目特性，常规 Web 经验（HTTP 状态码、RESTful 设计等）不写。

---

## 一、安全（强制）

### 1. XSS：innerHTML 输出必须 escapeHtml
JS 模板字符串拼接数据库字段到 innerHTML 前必须转义。

### 2. XSS：onclick 只传 ID
onclick 字符串参数会被 HTML 实体还原，escapeHtml 失效。函数内查数据，不要把字符串拼进 onclick。

### 3. CSRF：写操作必带 X-Requested-With
POST/PUT/DELETE/PATCH 头部必须 `X-Requested-With: XMLHttpRequest`。浏览器跨域无法伪造。
`create_app.py` 的 `before_request` 全局校验。

### 4. 权限：读+写都要检查
只装饰写方法，读方法会裸奔。`@require_permission(module, action)` 见 `utils/decorators.py`。

### 5. 异常响应不暴露内部信息
业务异常 → 友好中文消息；系统异常 → 通用 `"服务器内部错误"`，原始异常只记日志。
错误处理在 `create_app.py` 统一，路由层正常抛异常即可。

### 6. 文件上传必须校验扩展名+大小
白名单 + 上限，否则可上传恶意文件或耗尽资源。

---

## 二、错误处理

### 7. 业务异常 vs 系统异常分层
- 业务校验 → `raise ValueError('具体消息')` → 400 + 消息透传
- 系统异常 → `raise Exception(...)` → 500 + 通用消息 + logger.exception

不要用 Exception 抛业务错误。

### 8. 空请求不报 500
接收 JSON body 用 `request.get_json(silent=True) or {}`，不用 `request.get_json()`。

---

## 三、数据

### 9. 浮点数显示 toFixed(2)
前端展示前 `Number(x).toFixed(2)`，避免 `0.1 + 0.2 = 0.30000000000000004`。

### 9.1 后端浮点运算必须 round(2) (强制)
数量/重量 (quantity/weight) 参与运算或比较前必须 `round(..., 2)`，尤其：
- **减法后与 0 比较**（如 `剩余 = a - b; if 剩余 < 0`）→ 先 `round(a - b, 2)` 再比较。`7.3 - 7.3000000000000001 = -1.78e-15` 会被误判为负数
- **数据库比较**（`WHERE quantity >= ?`）→ 用 `ROUND(quantity, 2) >= ?`（SQLite）或 `round(py值, 2)`（Python）
- **数量上限校验**（`退回数量 > 实际用量`）→ 两侧都 `round`，防 `7.3 > 7.29999` 误拦截

曾出现 3 次同类 bug（出库审核、退库审核、库存扣减），全部因减法后未 round 产生微负/微差。

### 10. 避免重复查询
- **N+1**：循环内逐行查 DB → 先 `WHERE id IN (...)` 批量查，dict 缓存结果
- **JOIN 行重复**：LEFT JOIN 一对多产生重复行 → 改子查询避免行膨胀

### 12. 分页参数用 utils.pagination
分页参数上限用 `utils.pagination.get_per_page(default, max_value)`，不要手写 max/min。

### 13. 导出功能不限制分页
导出接口必须能返回全量，传 `per_page=None`。

### 14. 批量操作 commit 策略
- 原子操作（审核、转账）：全成功才 commit，任一失败 rollback
- 批量导入（Excel）：逐行 commit，失败行跳过继续，返回成功/失败统计

---

## 四、前端

### 15. 统一 HTTP 客户端
所有 API 调用用 `apiRequest()`（`static/js/app.js`），不用裸 fetch。
集中管理鉴权、CSRF、错误处理、401 跳转。

### 16. 权限按钮用服务端渲染
用 Jinja2 `{% if has_perm(...) %}`，不用 JS 隐藏（会闪烁）。

### 17. 模板变量注入 JS 处理空值
模板变量注入 `<script>` 用 `{{ var | default(none) | tojson }}`，未定义变量会渲染 `undefined` 报错。

---

## 五、SQL

### 18. 禁止 SELECT *
查询必须写明列名。`*` 浪费带宽，表结构变更时可能破坏代码。

### 19. LIKE 通配符必须转义 + ESCAPE
用户输入做 LIKE 必须 `escape_like()` 转义，SQL 加 `ESCAPE '\\'`（Python 双反斜杠，反斜杠作转义符）。
详见 `utils/sql.py`。

### 20. 动态 UPDATE 用 utils.sql.build_update_sql
动态 UPDATE 带字段白名单防 SQL 注入和误改敏感字段。

### 21. 业务规则集中定义
同一规则不在 SQL 端和 Python 端重复。抽 `_rule()` 函数，两端共用。

---

## 六、权限系统

### 22. 权限检查从 session 读，不走 DB
`session.permissions` 已缓存。变更后需重登录生效（接受此限制）。
装饰器见 `utils/decorators.py`。

### 23. 角色删除检查引用
有用户关联的角色拒绝删除，避免用户权限丢失。

---

## 七、消息与日志

### 24. 用户消息一律中文
API 响应的 error/message 全中文，不混英文。

### 25. except 必须 logger.exception
`except Exception` 块必须 `logger.exception(...)` 记录堆栈，否则生产环境无法排查。

---

## 八、架构与代码组织

### 26. Page 路由与 API 路由分 Blueprint
- 页面路由：单独的 Blueprint（如 `pages_bp`），渲染模板
- API 路由：按模块分 Blueprint，返回 JSON

不在 `create_app()` 内直接 `@app.route`。

### 27. Route 只调 Service，不直接碰 DB
写操作统一 `ValueError` → 400，`Exception` → 500 + logger。
Service 层负责事务、引用检查、业务规则。

### 28. import 风格
- 所有 import 顶部（Flask 循环导入除外）
- 顺序：标准库 → 第三方 → 本地
- `logger = ...` 放 import 之后

### 29. 死代码及时清理
重构后遗留的旧方法、旧调用、未使用 import 同步删除。
定期扫描 `# noqa`、`# type: ignore` 抑制注释。

---

## 九、本项目特性（强制）

### 30. SECRET_KEY 每次启动随机生成
`secrets.token_hex(32)`，重启后 session 失效。设环境变量 `SECRET_KEY` 可持久化。
**不硬编码，不写文件。**

### 31. 限流/缓存 dict 用 LRUDict
模块级 dict 必须用 `LRUDict(maxsize=...)`，防长期运行内存泄漏。
登录限流（IP+账号，5 次/15 分钟）已用 `LRUDict(maxsize=10000)` 实现。

### 32. SQLite 不开 foreign_keys
引用检查在 Service 层手动做。业务层报错可控，避免 SQLite 抛 IntegrityError 时上层难处理。

### 33. 业务连续性优先
单步改动涉及多层（装饰器/Service/页面/模板）时，逐层回归测试。
重构允许保留兼容旧 API 一段时间（见 `docs/代码质量改进记录.md`）。

### 34. 文档与代码同步
修改表结构、业务规则、权限模型时，同步更新：
- `docs/项目说明.md`（架构、运行、数据库约定）
- `docs/业务逻辑.md`（业务规则）
- `docs/权限管理.md`（权限矩阵）
- `docs/数据字典.md`（表结构）
- `docs/代码质量改进记录.md`（记录决策和教训）

删除与其他文档重复的内容；规范条文消除歧义，加代码示例。
