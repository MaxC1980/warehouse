# 通用开发规范

跨项目适用的 Web 开发规范，从实际修复中提炼。

---

## 一、安全

### 1. XSS 防护：innerHTML 必须转义
所有拼接到 innerHTML 的数据必须经过转义函数处理。不转义会导致存储型 XSS。
```javascript
// 正确
element.innerHTML = `<td>${escapeHtml(user.name)}</td>`;
// 错误
element.innerHTML = `<td>${user.name}</td>`;
```

### 2. XSS 防护：onclick 不传字符串参数
onclick 中的字符串参数会被 HTML 解析器先还原实体再执行 JS，导致转义失效。只传 ID，函数内部查数据。
```javascript
// 正确
onclick="editUser(${user.id})"
// 错误（escapeHtml 的 &#39; 会被还原为 '）
onclick="editUser(${user.id}, '${escapeHtml(user.name)}')"
```

### 3. CSRF 防护
所有写操作（POST/PUT/DELETE/PATCH）必须校验请求来源。两种方案：
- 自定义 header（如 `X-Requested-With: XMLHttpRequest`）— 浏览器跨域无法设置
- CSRF token — 需要生成/存储/轮换

### 4. 权限检查覆盖所有路由
读操作和写操作都必须检查权限。只检查写操作会导致任意登录用户可读取全部数据。
```python
# 正确：读+写都检查
@require_permission('material', 'view')
def get_materials(): ...

@require_permission('material', 'edit')
def create_material(): ...
```

### 5. 异常不暴露内部信息
错误响应不返回异常详情（含数据库表名、列名、SQL 语句）。业务异常返回友好消息，系统异常返回通用错误。
```python
# 正确
except ValueError as e:
    return {'error': str(e)}, 400  # 业务异常，消息可控
except Exception:
    logger.exception('操作失败')
    return {'error': '服务器内部错误'}, 500  # 系统异常，隐藏细节
```

### 6. 文件上传必须校验
校验扩展名（白名单）和文件大小（上限）。不校验可被上传恶意文件或超大文件耗尽资源。
```python
ALLOWED_EXTENSIONS = {'xlsx', 'xls'}
MAX_CONTENT_LENGTH = 10 * 1024 * 1024  # 10MB

ext = filename.rsplit('.', 1)[-1].lower()
if ext not in ALLOWED_EXTENSIONS:
    return {'error': '格式不支持'}, 400
```

## 二、错误处理

### 7. 业务异常 vs 系统异常分层
业务校验抛 `ValueError`（可控消息），系统异常用 `Exception`（通用消息）。不要用 `Exception` 抛业务错误。
```python
# 正确
if quantity < 0:
    raise ValueError('数量不能为负')
# 错误
if quantity < 0:
    raise Exception('数量不能为负')
```

### 8. 异常必须记录日志
`except Exception` 块必须记录异常堆栈，否则生产环境无法排查。
```python
except Exception as e:
    logger.exception('操作失败')  # 记录完整堆栈
    return {'error': '服务器内部错误'}, 500
```

### 9. 空请求不报 500
接收 JSON body 的接口必须处理空请求或非 JSON 请求。返回友好错误，不报 500。
```python
# 正确
data = request.get_json(silent=True) or {}
# 错误（空请求会报 400/500）
data = request.get_json()
```

## 三、数据

### 10. 浮点数显示必须格式化
浮点运算会产生精度问题（如 `0.1 + 0.2 = 0.30000000000000004`）。显示时必须四舍五入。
```javascript
// 正确
Number(quantity).toFixed(2)  // "1.50"
// 错误
quantity  // 1.4999999999999998
```

### 11. N+1 查询必须批量优化
循环内逐行查数据库是 N+1 问题。先批量查询，用 dict 缓存结果。
```python
# 正确
ids = list(set(item['material_id'] for item in items))
cursor.execute(f"SELECT id, name FROM material WHERE id IN ({placeholders})", ids)
name_map = {row['id']: row['name'] for row in cursor.fetchall()}

for item in items:
    name = name_map.get(item['material_id'])
```

### 12. LEFT JOIN 一对多用子查询
LEFT JOIN 可能产生重复行时，用子查询替代。
```sql
-- 正确
SELECT (SELECT name FROM table2 WHERE id = t1.ref_id LIMIT 1) FROM table1 t1
-- 错误（重复行）
SELECT t2.name FROM table1 t1 LEFT JOIN table2 t2 ON t2.ref_id = t1.id
```

### 13. 分页参数必须有上下限
分页参数必须限制范围，防止负数、零、超大值。
```python
per_page = max(1, min(per_page, max_value))
```

### 14. 导出不限制分页
导出功能应返回全部数据，不应用分页截断。
```python
# 正确
data = get_data(per_page=None)  # 无限制
# 错误
data = get_data(per_page=10000)  # 超过部分丢失
```

## 四、前端

### 15. 统一 HTTP 客户端
所有 API 调用用统一的请求函数，集中管理鉴权、CSRF、错误处理、401 跳转。不用原生 fetch 分散调用。
```javascript
// 正确
const result = await apiRequest('/materials', { method: 'POST', body: JSON.stringify(data) });
// 错误（绕过鉴权/CSRF/错误处理）
const response = await fetch('/api/materials', { method: 'POST', body: data });
```

### 16. 权限控制用精确匹配
页面/功能权限用精确标识符（如路由 endpoint、权限名）映射，不用路径前缀匹配。前缀匹配会导致误判。
```python
# 正确：endpoint 精确匹配
PERMISSIONS = {'material_edit': ('material', 'edit'), 'material_view': ('material', 'view')}
required = PERMISSIONS.get(request.endpoint)

# 错误：前缀匹配（/materials/1/edit 会被 /materials 误判为 view）
for prefix, perm in PERMISSIONS:
    if request.path.startswith(prefix):
        ...
```

### 17. 模板变量注入 JS 必须处理空值
模板变量注入 `<script>` 时，必须处理变量未定义的情况。
```javascript
// 正确（Undefined → null）
const orderId = {{ order_id | default(none) | tojson }};
// 错误（Undefined 报错）
const orderId = {{ order_id | tojson }};
```

### 18. 按钮权限用服务端渲染
权限控制的按钮用服务端条件渲染（如 Jinja2 `{% if %}`），不用 JS 隐藏（会闪烁）。
```html
<!-- 正确 -->
{% if has_perm('material', 'edit') %}<button>新增</button>{% endif %}

<!-- 错误（页面加载瞬间可见） -->
<button id="add-btn">新增</button>
<script>if (!hasPerm) document.getElementById('add-btn').style.display = 'none';</script>
```

## 五、权限系统设计

### 19. 权限矩阵覆盖所有操作类型
权限矩阵渲染时，操作类型列表要包含所有可能的类型（如 view/edit/approve/manage），不能只写死部分。按模块过滤适用的操作类型。

### 20. 权限变更要考虑 session 缓存
修改角色权限或用户角色后，已登录用户的 session 缓存不更新。要么接受重新登录限制，要么用服务端 session 或版本号机制。

### 21. 角色删除要检查引用
删除角色前检查是否有用户关联。有引用则拒绝删除，避免用户权限丢失。
```python
cursor.execute("SELECT COUNT(*) FROM user_role WHERE role_id = ?", (role_id,))
if cursor.fetchone()[0] > 0:
    raise ValueError('该角色下有用户，不能删除')
```

## 六、代码质量

### 22. 不用未使用的 import
删除未使用的 import，保持代码整洁。

### 23. 批量操作的 commit 策略
根据业务场景选择 commit 策略，不要盲目逐行 commit：
- **原子操作**（如审核、转账）：全部成功才 commit，任一失败则 rollback
- **批量导入**（如 Excel 导入）：逐行 commit，失败行跳过继续，返回成功/失败统计

```python
# 原子操作：全部成功才 commit
try:
    for item in items:
        process(item)
    conn.commit()
except Exception:
    conn.rollback()
    raise

# 批量导入：逐行 commit，失败继续
for row in data:
    try:
        insert(row)
        conn.commit()
        success += 1
    except Exception:
        errors.append(...)
        failed += 1
```

### 24. 不用 SELECT *
查询必须写明需要的列名。`SELECT *` 会返回不需要的列，浪费带宽，且表结构变更时可能破坏代码。

### 25. 页面路由调 Service 要有异常处理
页面路由直接调用 Service 方法时，必须有 try/except。异常时重定向或返回错误页面，不暴露原始错误。

## 七、SQL

### 26. LIKE 通配符必须转义
用户输入用于 LIKE 查询时，必须转义 `%` 和 `_`，防止被当作通配符。
```python
# 正确
keyword = keyword.replace('%', '\\%').replace('_', '\\_')
cursor.execute("SELECT * FROM t WHERE name LIKE ? ESCAPE '\\'", (f'%{keyword}%',))
# 错误（用户输入 '100%' 会匹配任意字符）
cursor.execute("SELECT * FROM t WHERE name LIKE ?", (f'%{keyword}%',))
```

## 八、国际化

### 27. 面向用户的消息用中文
所有 API 响应的 error/message 字段用中文，不用英文。错误提示和成功提示都适用。
```python
# 正确
return {'error': '入库单不存在'}, 404
return {'message': '入库单已删除'}
# 错误
return {'error': 'Order not found'}, 404
```

## 九、架构与重构

### 28. 大函数拆分模式
超过 100 行的函数应拆分为多个子函数，每个子函数单一职责。
- 主函数做编排（< 30 行）
- 子函数做具体逻辑（< 50 行）
- 子函数命名以 `_` 前缀表示内部使用

### 29. 业务规则集中定义
避免同一业务规则在多处重复定义。抽为独立函数，SQL 端和 Python 端共用。
```python
# 正确：规则集中
def _expiry_filter_bounds(status):
    """status → (operator, value, require_non_null)"""
    ...

# SQL 端和 Python 端都调用
bounds = _expiry_filter_bounds(status)
```

### 30. 动态 SQL 构建工具
重复的动态 UPDATE SQL 构建模式应抽为工具函数，带字段白名单防注入。
```python
def build_update_sql(table, data, allowed_fields, id_column='id'):
    """根据 data 中存在的字段动态构建 UPDATE SQL"""
    updates = []
    params = []
    for field in allowed_fields:
        if field in data:
            updates.append(f"{field} = ?")
            params.append(data[field])
    ...
```

### 31. 页面路由与 API 路由分离
页面路由（渲染模板）和 API 路由（返回 JSON）应分 Blueprint，不要混在应用工厂函数内。
- 页面路由: 专门的 Blueprint
- API 路由: 按模块分 Blueprint

### 32. Service 层抽取
Route 层不要直接操作 DB，应通过 Service 层。写操作统一 `ValueError` → 400，`Exception` → 500 + logger。

### 33. import 风格统一
- 所有 import 放文件顶部，不在函数内延迟 import（Flask 循环导入除外）
- import 顺序: 标准库 → 第三方 → 本地
- 变量定义（如 `logger = ...`）放在所有 import 之后

### 34. 死代码清理
- 删除未使用的 import、变量、函数
- 重构后遗留的旧方法应删除，测试中的旧调用同步更新
- 定期扫描 `# noqa`、`# type: ignore` 等抑制注释

### 35. 文档与代码同步
- 数据字典必须与实际表结构一致
- 删除与其他文档重复的内容
- 规范条文消除歧义，加代码示例

### 36. 限流/缓存字典用 LRU 防内存泄漏
模块级 dict 用于限流/缓存时，必须设容量上限，防止长期运行内存累积。
```python
from collections import OrderedDict

class LRUDict:
    def __init__(self, maxsize):
        self.data = OrderedDict()
        self.maxsize = maxsize

    def __setitem__(self, key, value):
        if key in self.data:
            self.data.move_to_end(key)
        self.data[key] = value
        if len(self.data) > self.maxsize:
            self.data.popitem(last=False)  # 淘汰最旧
```
